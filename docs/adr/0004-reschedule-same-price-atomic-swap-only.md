# Reschedule is a same-price atomic slot swap with no money movement

Rescheduling cancels the old slot(s) and claims the new slot(s) in a single transaction. No refund is issued and no new charge is made — it only works when the total price of the new span matches `AmountCharged` on the original Booking. If the prices differ, the user must cancel (triggering a refund per the cancellation window) and rebook. This keeps the payment model simple: one charge per Booking, one refund if cancelled. A partial-charge-difference flow was rejected as too complex for V1.

**Extended to block bookings (ADR-0008):** a reschedule moves the entire N-slot span as a unit — same slot count, new contiguous start. All N new slots must be free, and the summed price of the new span must equal `AmountCharged`. This generalizes the same-price-swap rule rather than special-casing single-slot bookings; it was not handled when ADR-0008 (multi-slot block bookings) was introduced, and the implementation silently broke for blocks until this was caught.
